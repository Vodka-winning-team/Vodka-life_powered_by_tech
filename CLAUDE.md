# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

**Verifye** ("avan ou peye", formerly FraudLens Moris) is an app built with **Expo (React Native + TypeScript)** whose checks all run on the phone, offline. An optional server (`server/`, written from scratch on Sat 14 Nov, decision 23) adds live link checks, reports from other phones and a Kreol voice behind one "Online checks" switch. It runs as an Android APK, on iPhone through Expo Go, and on the web. (Switched from Kotlin on Fri 13 Nov ~18:15; see the box at the top of `docs/TASKS.md`. Do not write new Kotlin.) It checks a suspicious SMS, WhatsApp or email message, shows its warning signs (X-Ray) and the official-register checks, then tells the user what to do now. The overseas-job check is the lead story. Built for the hackathon **Life Powered by Tech**, Theme 1. Hard deadline: **Sat 14 Nov 2026, 12:30**.

1. **`docs/TASKS.md`** is the plan we're following: each person's tasks, file ownership and the contract. Where it differs from `PROJECT.md`, `TASKS.md` wins. Shield came back as opt-in "Automatic checking" (decision 15). `docs/decisions.md` has every later change.

## How each session works

There are four teammates (A Data, B Engine, C App, D Pitch). Each runs their own Claude session and states their role in the first message. In a session:

- **Do only that person's tasks, one step at a time, in the order listed in `docs/TASKS.md`.**
- **Only create or edit files in the folders that person owns.**
  - A: `data/` and `app/src/main/assets/data/`
  - B: `src/engine/` and `server/`
  - C: `src/` (except `src/engine/`), `assets/`, `package.json`, `app.json`, `tsconfig.json`, `eslint.config.js`
  - D: `README.md` and `docs/`

  If another person's folder needs a change, say so instead of making it.
- After each step:
  1. Tell the user how to check the step themselves.
  2. Explain what you did in 5 plain lines.
  3. Add one line to `docs/ai-log.md`: time, person, what Claude did, what was checked.
  4. Run `git pull --rebase`, then `git add <own folders only>`.
  5. Commit with the person's letter as a prefix (e.g. `A: agencies.json, 79 licences`) and push. If the push is rejected, pull with rebase and push again.

  Push at least once an hour. The judges look at the commit history.
- Keep each change small enough that the person can explain it to a judge.
- The contract in `docs/TASKS.md` §2 changes only if A, B and C all agree. Update `TASKS.md` in the same commit.

## Architecture

```
data/raw/        official source files downloaded in a browser (gitignored; bom.mu and FSC block scripts)
data/scripts/    Python, one script per source (pdfplumber) -> JSON; validate.py checks every file
src/app/         screens (Expo Router: every file is a screen): index (Scan), result, job, actions, history, sources
src/components/  ui.tsx: Screen, Label, Card, Button, Chip, LevelBanner, HighlightedText
src/constants/   theme.ts (ALL colours and sizes), strings.ts (ALL UI text, en/fr/mfe)
src/lib/         data.ts (loads the 5 JSON files, builds the engine), store.tsx (current check + history), sample.ts (dev only)
src/engine/      pure TypeScript engine, imported as @/engine; NO react-native/expo imports; tests in __tests__/
app/src/main/assets/data/   agencies.json, fee_rules.json, banks.json, fsc_alerts.json, cert_alerts.json (path kept from the Kotlin plan)
server/          optional FastAPI server (B): live link checks, reports as salted hashes, pay check, lessons, myt voice; keeps no message
src/widget/      Android home-screen widget
docs/            TASKS.md, decisions.md, ai-log.md, demo-messages.md, test-cases.md, sources.md, user-tests.md
```
`android/` and `ios/` are generated by `npx expo prebuild` and gitignored. Never edit them by hand; configure in `app.json`.
Expo changes every SDK: before using an Expo or React Native API, check the docs for SDK 58 (https://docs.expo.dev/versions/v58.0.0/). Add packages with `npx expo install <pkg>`, never `npm install <pkg>`.

Data flows like this:

1. A's scripts write the JSON into `app/src/main/assets/data/`.
2. `src/lib/data.ts` bundles all five files and passes their text to `DataSet.fromJson(...)`.
3. `new Engine(data).check(text, jobAnswers)` returns a `CheckResult`: a `Level` plus a list of `Finding`s (fixed `kind` key, highlight `{ start, end }` ranges into the message with end not included, and a `Source`) and official `Contact`s.
4. The screens render that result.

`suggestAgencies(text)` fuzzy-matches register agencies named in the message, for the Job check screen. The exact signatures and JSON fields are in `docs/TASKS.md` §2. Code against them exactly.

Level rule:

- **STOP** if any of these: a request for a code or PIN; a link that isn't the official domain of the bank named in the message; a job fee the employer should pay (Act 2023 s.5, Regs 2025 reg 7(2)); a match with an FSC alert.
- **CAREFUL** if there are other warning signs.
- **NONE** otherwise.

Note that "Your code is 123456, never share it" must produce **no** finding.

The engine's test targets are D's 6 demo messages (`docs/demo-messages.md`) and A's 15 cases (`docs/test-cases.md`).

## Commands

- First time: `npm install`
- Run the app: `npx expo start`, then scan the QR code with **Expo Go** (Android or iPhone, same Wi-Fi), or press `w` for the web
- Engine tests (no phone needed): `npm test`; one file: `npx jest src/engine/__tests__/engine.test.ts`
- Server (optional): `cd server`, `python -m venv .venv`, install `requirements.txt`, copy `.env.example` to `.env` (git-ignored keys), then `run_server.bat` on Windows or `.venv/bin/python -m uvicorn verifye_server.main:app --host 0.0.0.0 --port 8000`; tests: `.venv/bin/python -m pytest -q`
- Before every commit: `npm run typecheck` and `npx eslint src`
- Web build: `npm run export:web` (output in `dist/`)
- Android APK (C's laptop): `npx expo prebuild -p android`, then `cd android && gradlew assembleRelease` → `android/app/build/outputs/apk/release/app-release.apk` (needs `JAVA_HOME` = Android Studio's `jbr` and `ANDROID_HOME`)
- Validate the data: `python data/scripts/validate.py`. It checks for valid JSON, unique ids, `source_url` and `snapshot` on every row, phone numbers starting with `+230`, and dates in YYYY-MM-DD format.

## Rules that are easy to break

- **Write all code from scratch.** Never copy from the old FraudLens repo or from `E:\Hackathon`.
- No AI/ML models. Every check runs offline on bundled data; the optional server only adds live link checks, reports and the voice, and never stores a message.
- Use only real records from official sources; never fake or placeholder data. Every record has `source_url` and `snapshot`. Copy law clause references exactly from the PDFs.
- Privacy:
  - Never store the names of people (directors or anyone else). FSC alerts list organisations only.
  - Never ask the user for codes, PINs or bank details.
  - History is saved only when the user taps Save.
- UI wording: never say "safe", "genuine", "scam" or "illegal". Use "Not found in the Ministry list of 4 Nov 2026" or "Listed, but this does not prove the message is from them".
- The dial button always uses the official number, never a number taken from the message.
- All UI text goes in `src/constants/strings.ts` (`en`, `fr`, `mfe` for Kreol). Colours and sizes go in `src/constants/theme.ts`, so the surprise card can be handled quickly.
- Demo messages are fictional and labelled that way.
- Cut order if behind: FSC/CERT first, then French, then job follow-up. Never cut features 1–8.
